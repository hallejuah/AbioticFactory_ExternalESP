# v1.9 — Paginated outline survey with state comparisons

This read-only diagnostic resolves a limitation of v1.8: every F12 press
checked the first 80 cached actors again, even if the scanner had hundreds.

## Testing

1. Build Windows x64 Release from `feature/v1.9-paginated-outline-survey`.
2. Start Abiotic Factor and the ESP overlay.
3. Press **F12** repeatedly. Each press examines the next 80 indices of
   the currently cached categorized actor list.
4. Check `abiotic_outline_survey.txt` beside `AbioticESP.exe`.
5. Each block logs `indexRange=[start,end)`, `nextIndex`, `total` and
   `PASS COMPLETE` when the end of the list is reached.
6. Press F12 again after completion to wrap to index 0 for another pass.
   To compare state before/after gameplay changes, interact with a nearby
   object and revisit its page while the cached list remains stable.
7. Send the entire file (and optionally mention whether a visible in-game
   highlight was on screen).

For a stable 733-actor list, approximately **10 F12 presses** cover the
list (9 full groups of 80 plus a group of 13). F2 remains disabled; the
branch makes **no game-memory writes**.

## What is reported

Each entry includes reflected candidates for `OutlineMask`,
`ComponentEnabled`, `RegisteredComponents`, and mesh CustomDepth when
an owned skeletal mesh was found.

- `CANDIDATE` means mask is nonzero or a list count is positive. It does
  **not** prove the game rendered an outline.
- `CHANGE` means a previously observed actor address has a changed mask,
  registered count, enabled byte, outline component pointer or known
  CustomDepth bit. Baselines live in memory and are lost when ESP exits.
- The actor-list signature is order-sensitive. If a scan adds/removes/reorders
  actors, the next F12 restarts at index 0 and logs `RESET`; this avoids
  pretending that an outdated cursor provides full coverage.
- On a new game world or disconnection, the observation history resets.

## Scope and limits

80 actor indices per F12; at most 0x1000 bytes of actor pointer slots,
8 outline components per actor, 12 displayed registered component classes
and 8,000 directly-owned UObject validations per call. Only categorized
actors retained by the existing scanner are included. It is **not** a full
UObject-world search. No UE functions, rendering hooks or writes.

Windows VS 2026 compilation and in-game result remain unverified.
