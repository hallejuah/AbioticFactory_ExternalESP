# v0.5 — smoother external ESP, silhouette research

## Implemented
- Overlay timer reduced from 100 ms to 16 ms (nominal ~60 Hz).
- Camera is read on each timer tick and world positions are projected against the freshest camera.
- Actor positions/health are cached for up to ~33 ms (~30 Hz actor sampling).
- The actor sample cache is cleared on successful actor rescans, level identity changes, and game reconnection.
- Only external, read-only memory reads are used.

## Test on Windows
1. Build with MSVC x64 in Release.
2. Stand near a stationary monster and rotate camera rapidly: labels should move less jerkily than v0.4.
3. Walk beside a moving enemy and check up to ~33 ms actor sampling latency.
4. Restart the game and stream between levels; ensure no stale labels or crashes.
5. Compare CPU use with v0.4, particularly in areas with 100+ actors.
6. Verify F3–F10 and End still work.

## Silhouette research — not implemented yet
A true per-pixel model silhouette cannot be drawn from Actor RootComponent location alone. Current code has no verified SkeletalMeshComponent pointer, skeletal bone transforms, mesh assets, mesh triangles, occlusion mask, or renderer depth information.

Recommended next diagnostic iteration:
1. Enumerate actor-owned UObject components using **validated UE class metadata** on known NPC actors.
2. Identify and validate any SkeletalMeshComponent addresses and their ownership; never guess offsets from unrelated builds.
3. Determine whether an external-only viewer can access enough skeletal pose data to draw a useful approximation. Skeleton/bone lines do not equal a filled mesh silhouette.
4. If exact contour is required, clarify whether engine-rendered outline mechanisms are acceptable, since external read-only GDI overlay cannot access visible mesh pixel masks directly.

Do not call a rectangle or capsule an exact silhouette. Keep external memory access read-only.
