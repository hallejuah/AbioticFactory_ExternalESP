# ESP v0.9 — bounded candidate FProperty chain traversal

## Rationale
v0.8 reported plausible first property names under UClass +0x50, including
`UberGraphFrame`, `SkeletalMesh`, `OverrideMaterials`, and `PrimaryComponentTick`.
Those names are suggestive, but a correct FField/FProperty layout and field offsets
remain unverified in this game's engine build.

## Usage
1. Build `feature/v0.9-fproperty-chain-probe` (x64 Release, Visual Studio 2026).
2. Start the game and ESP. Position a living **Pest** or **Carbuncle** near the screen centre.
3. Tap **F12** once. New report: `build/Release/abiotic_property_chain.txt`.
4. Repeat with a second enemy and share the report. Multiple entries are appended.
5. F11 remains the mesh component probe. Earlier v0.8 reflection code is retained,
   but F12 now runs the v0.9 inspector.

## Bounds and evidence levels
- Owner and component class validated before any speculative lookup.
- UClass inheritance depth capped at 7, candidate field chain at 24 per class.
- Candidate `Class+0x50` head, `FField+0x18` next, `FField+0x20` FName
  are hypotheses based on earlier results, not verified engine metadata.
- Only follow a candidate next pointer when the pointed-to node also has a
  plausibly decoded FName. Check for cycles and stop on invalid pointers.
- Integer candidate offsets +0x44/+0x48/+0x4C/+0x50 are *not* verified
  `Offset_Internal` or property types; the report does not assert they are.
- The output is not yet a complete property dump.
- External read-only process access; no memory writes or game rendering hooks.

## Goal
Use repeated, internally consistent name chains to establish which suspected
FProperty metadata fields can be promoted to verified offsets. Real mesh
silhouettes require additional geometry/pose or renderer mask data.
