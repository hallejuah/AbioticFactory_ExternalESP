# v0.8 — experimental UE5 reflection inspector

## Goal
Investigate whether the verified `OutlineComponent_C` and `SkeletalMeshComponent` have discoverable reflective metadata in this exact game build. Do not assume UE5 engine offsets from another version are correct.

## How to test
1. Switch to `feature/v0.8-reflection-inspector`, configure CMake Release x64 using Visual Studio 2026, then compile.
2. Start game and ESP. Select a living visible Pest or Carbuncle near the centre.
3. Press **F12** once. Report: `build/Release/abiotic_reflection_probe.txt`.
4. Press F12 on another enemy instance and compare whether names and class candidate pointers remain consistent.
5. Upload only `abiotic_reflection_probe.txt`.

F11 continues to produce `abiotic_mesh_probe.txt`. The previous F12 outline-pointer diagnostic remains in the repository but F12 now runs the reflection probe instead.

## Safety/accuracy of findings
- Actor `+0x320` and `+0x9D8` component pointers are validated by UObject class and Outer owner before inspection.
- Class inheritance chain uses `UStruct::SuperStruct +0x40` (verified in earlier diagnostics).
- Candidate metadata head offsets `+0x48` and `+0x50`, and candidate FField name offsets `+0x20/+0x28/+0x30` are **hypotheses**, not validated structure layouts.
- The tool reads only a bounded first node per candidate class head and does not chase unknown next pointers.
- The output is investigative, not a reliable Blueprint property dump or offsets mapping.
- No writes, injection, or hooks. No exact silhouette, bones, stencil values, or mesh geometry can be inferred from this report alone.

## Test expectations
Check the resulting MSVC compilation and report; unknown fields might show no trustworthy names. That is acceptable; do not interpret speculative names as verified until corroborated across different class instances and engine metadata anchors.
