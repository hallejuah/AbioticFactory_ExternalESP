# ESP v0.7 — OutlineComponent reference research

## Observations motivating this probe
Read-only F11 reports for Pest and Carbuncle both identified:
- `Actor+0x320`: `SkeletalMeshComponent`
- `Actor+0x9D8`: `OutlineComponent_C`

These offsets **are not validated for other enemy classes**. The names do not prove that a ready-made outline mask is accessible externally.

## How to test
1. Switch to branch `feature/v0.7-outline-component-research`.
2. Build CMake Release/x64 with Visual Studio 2026.
3. Run ESP, find a visible Pest and bring it near screen centre.
4. Press **F12** once. This creates/appends to `abiotic_outline_probe.txt` next to `AbioticESP.exe`.
5. Repeat on Carbuncle; optionally test Peccary/Security Robot to see whether the same layout validates. Failures on those actors are expected and **not** evidence of missing components.
6. Send the text report. You can remove transient pointer address values before sharing.

## What the probe actually does
- Does **not** change any game memory or enable any visual effects.
- Resolves actor fields only after confirming a known hostile UObject.
- Verifies both component class names and `OuterPrivate == actor`; exits early if either test fails.
- Reads the first 0x300 bytes of each verified component.
- Finds explicit references to actor/mesh/outline and a limited number of validated UObject pointer/class links. Limits: 20 general candidate class checks per component.
- Does **not** decode Blueprint property names, skeleton bones, stencil bits, or mesh triangles.

## What comes next
If the report yields useful typed references, validate the specific component relationships using several live actor instances before designing an external rendering approximation. A true pixel-exact game-engine outline cannot be obtained merely by reading the component name.
