# v1.1 — Bone Transform Inspector

This phase probes candidate cached animation transforms for a single visible hostile NPC. It **does not** draw a silhouette or a skeleton.

## Usage

1. Switch to `feature/v1.1-bone-transform-probe` and compile Release/x64.
2. Open the game and ESP, centre the camera near a stationary Pest.
3. Press **F12** once; wait, then move the Pest or observe it walking and press **F12** again.
4. Report: `build/Release/abiotic_bone_transforms.txt`. Each press appends another snapshot.
5. Repeat with Carbuncle if present. Upload the text file for comparison.

F11 still runs the actor component diagnostic.

## Read-only and bounds

- Verifies hostile actor UObject and its directly owned `SkeletalMeshComponent`.
- Candidate field offsets from v1.0: `mesh+0x978` and `mesh+0x988`.
- Reads a candidate 16-byte TArray header; rejects unaligned/bad pointers, negative or zero counts, counts greater than 32, and capacity inconsistencies.
- Samples a maximum of 12 entries from each array; bounded to at most 1152 bytes per tested layout.
- Tests both **48-byte float** and **96-byte double** `FTransform` layout hypotheses, using finite values, quaternion norm and scale/translation sanity checks.
- Does not dereference mesh assets, modify the game, or walk unknown UE pointers.

## Interpreting the report

A high plausibility score suggests a promising layout, **not** proof. The engine's `FTransform` storage, bone-parent hierarchy and mesh geometry are still unknown. Component-space transforms cannot yet be converted to accurate world-space silhouettes. No bone names are included.

Compare the first and second snapshots: plausible translation changes from animation may help validate the correct layout. Windows/MSVC compilation and actual game behavior need local verification.
