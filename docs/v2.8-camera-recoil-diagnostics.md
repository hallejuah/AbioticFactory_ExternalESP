# v2.8 — Numpad3 camera recoil diagnostics (read-only)

The user confirmed that the v2.7 Numpad1 status said
`NoRecoil trial active (1.5s)`, but camera recoil was not visibly
reduced. **Armed does not mean a successful memory write.** This version
adds an independent read-only camera measurement.

## Controls
- **NumPad1**: existing 1.5-second experimental recoil trial (unchanged).
- **NumPad2**: existing 2-second rifle-value CSV.
- **NumPad3**: new **2-second camera rotation and recoil capture**.
- **NumPad0**: on-screen key reminder.
- Enable Num Lock; Box ESP remains unchanged.

## Test
1. Equip `Abiotic_Weapon_QuillRifle_C` in solo game.
2. Record baseline: press NumPad3 and fire several shots during the
   next 2 seconds **without NumPad1**.
3. Record trial: wait until the rifle is idle; press NumPad3 then
   immediately press NumPad1 and fire during the trial.
4. Repeat if needed. The file
   `abiotic_camera_recoil.csv` is appended beside AbioticESP.exe.
   Send the CSV, noting the order of baseline and experimental captures.

## CSV
`elapsed_ms,camera_pitch,camera_yaw,camera_roll,last_fire,aim_recoil,controller_track,recoil_track,fire_delay,trial_write_count`

- Camera rotation is obtained from the same validated
  `UE5::readCamera` cache the ESP already uses; it is **camera view**
  rotation, **not proven raw PlayerController.ControlRotation**.
- Trial write count is the accumulated count on the current/last
  NumPad1 session; compare increments *within* a capture. It may remain
  at an old positive value outside the active test.
- This is a best-effort timer-driven sampling loop (~20ms goal,
  maximum 100 samples or 2 seconds). CSV timestamps record actual gaps.
- Starting and sampling check the local player/character and Quill Rifle
  identities and the camera object. If these fail the capture stops.
- No new writes or engine calls. Numpad1's experimental behavior remains
  unproven. Rapid Fire is **not implemented**.

The PR has not been compiled or tested on Windows MSVC yet.
