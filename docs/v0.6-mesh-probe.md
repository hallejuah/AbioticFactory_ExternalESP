# v0.6 — manual enemy mesh component probe

## What this does
Press **F11** once with a **visible living hostile** near the screen center. The tool selects the nearest visible hostile to the crosshair and inspects up to 4096 bytes from that actor's UObject **in read-only mode**. It considers only pointer-aligned candidates and only accepts UE objects whose validated `OuterPrivate` equals the selected actor.

The diagnostics are appended to **abiotic_mesh_probe.txt** in the same directory as the ESP executable. They include actor class/address, actor-relative field offsets, UE class inheritance chains for direct-owned objects, and counts of possible mesh-derived classes.

This is a **heuristic**, not a complete UE component enumeration. It will miss components stored only in TArrays or other containers and does not read bones, vertices or mesh silhouettes. All detected offsets must be confirmed experimentally on the exact supported build.

## How to test
1. Pull the feature branch and compile in VS 2026, x64, Release.
2. Open the supported Abiotic Factor build and find a **Pest, Peccary, Carbuncle or Security Robot**.
3. Keep the hostile inside the ESP view, near screen center. Press **F11 only once**.
4. Open `build/Release/abiotic_mesh_probe.txt` (or the folder containing the executable).
5. Repeat once with a second enemy class and compare results.
6. Share only the text report if comfortable; raw addresses are transient, and the report does not contain game memory dumps.

## Guardrails
- `OpenProcess(PROCESS_VM_READ | PROCESS_QUERY_LIMITED_INFORMATION)` stays unchanged.
- Never writes to or hooks the game process.
- Max one 4 KiB actor read per F11 press plus pointer/class validation reads.
- Class inheritance is capped at 16 levels; direct-owned object report at 48 matches.
- No assumption that the selected actor has a mesh at a given offset.
- A true per-pixel outline needs visibility/geometry information not verified yet.
