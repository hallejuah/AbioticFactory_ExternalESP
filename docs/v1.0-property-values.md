# ESP v1.0 — read-only instance values research

## What it does
F12 targets one visible hostile closest to screen centre. The program validates
the actor, mesh and outline component class/owner relationships before looking
up a small allowlist of reflected property names.

- OutlineComponent_C: OutlineMask, RegisteredComponents, ComponentEnabled
- SkeletalMeshComponent: CachedBoneSpaceTransforms,
  CachedComponentSpaceTransforms, AnimScriptInstance

For each found field the diagnostic prints the proposed instance offset
(candidate metadata FProperty +0x44), a **candidate** FFieldClass type name,
and 16 raw bytes at the proposed instance address. A 16-byte TArray-like
header interpretation is shown for comparison only; it must not be treated
as proof that the field really is a TArray. No array elements are read.

## How to test
1. Build the feature branch in x64 Release using VS 2026.
2. Start Abiotic Factor and ESP, select a Pest near the crosshair.
3. Press **F12** once. Report is appended in
   `build/Release/abiotic_property_values.txt`.
4. Repeat with a second Pest, then Carbuncle if available.
5. Share the text file. No raw binary memory dump is generated.

## Limits and cautions
- Field names and metadata chains looked plausible in v0.9, but
  `class+0x50`, `field+0x18`, `field+0x20`, `field+0x44`
  and proposed FFieldClass name offsets are still **hypotheses**.
- Reported type labels and instance offsets are *not independently verified*.
- Raw bytes must not be interpreted as a validated boolean, mask, count,
  pointer, array, or bone transform without type/layout confirmation.
- Maximum field nodes 64 per class, maximum 7 parent classes. Unknown,
  cyclic and invalid links stop traversal.
- Every read uses the existing external ReadProcessMemory path.
- No memory writes, hooks, DLL injection, engine outlines or skeletal drawing.
- This is an investigative tool, **not yet a real ESP silhouette outline**.
