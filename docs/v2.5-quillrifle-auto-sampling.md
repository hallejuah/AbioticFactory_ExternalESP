# v2.5 — QuillRifle automatic sampling (read-only)

Previous v2.4 F11 snapshots of `Abiotic_Weapon_QuillRifle_C` found
`FireDelayDuration +0xB28 = 0` repeatedly and recoil track values that
did not change at the sampled instants. This does **not** establish
whether those properties are used for gameplay.

## Capture
- Equip the Needle Rifle / `Abiotic_Weapon_QuillRifle_C`.
- Press **F11**: start one **2-second** capture.
- **Shoot during those 2 seconds.** Sampling is triggered from the
  existing UI timer without a blocking sleep, aiming for approximately
  one row per 20 milliseconds (up to 100 rows).
- The session ends automatically; F11 again starts a new capture.
- The output is **`abiotic_quillrifle_samples.csv`** beside the ESP
  executable. Each run is appended as a separate CSV section.
- Repeat once standing idle and once while firing, then send the CSV.

Fields: elapsed wall-clock milliseconds, player `LastTimeFiredWeapon`,
held Quill Rifle `FireDelayDuration`, player spread/sway/recoil
candidate double values, two timeline track floats, burst counter.

## Guardrails and limitations
- Only begins after validated world/controller, local character alias
  agreement and `ItemInHand_BP` class identity.
- Rechecks the character and weapon class every sample and ends early
  if the held weapon changes.
- Uses read-only `Process::get`; does not write memory or change
  game mechanics. F2/F12 remain off and Box ESP remains available.
- Sampling cadence is **best effort**: UI work and scheduling can
  increase spacing; the CSV contains measured elapsed milliseconds.
- No inference about fire rate from a static zero-valued field.
- Windows x64 MSVC compile and live capture remain to be tested.
