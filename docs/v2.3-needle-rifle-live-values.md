# v2.3 — Needle Rifle live values (read-only)

v2.2 confirmed that the local character's `ItemInHand_BP` resolves to
`Abiotic_Weapon_QuillRifle_C` when the Needle Rifle is equipped, and to
`Weapon_Melee_Heavy_C` with a different weapon. v2.3 uses that confirmed
class identity to target the rifle-specific reflected property search.

## How to test
1. Switch to branch `feature/v2.3-needle-rifle-live-values` and build
   Windows x64 Release.
2. Launch the solo game and ESP; equip the Needle Rifle (Quill Rifle).
3. Press **F11** once while idle.
4. Fire several shots, then press **F11** again.
5. Switch to a different item and press **F11** again.
6. Send `abiotic_needle_rifle_research.txt` beside `AbioticESP.exe`.
   Please indicate which snapshot is idle / post-shots / other item.

## Report fields
- The already validated controller -> local character relationship,
  including two independent pointer aliases.
- Candidate double values at player-character offsets:
  `LastTimeFiredWeapon +0x1898`,
  `BulletSpread_Base +0x19C0`,
  `BaseGunSway_Multiplier +0x19D8`,
  `CurrentGunSway_Speed +0x19E0`,
  `AimRecoilAdditive +0x1A00`, plus an integer
  `CurrentWeaponBurstCounter +0x2878`.
- A validated current `ItemInHand_BP` UObject class from +0x1A50.
- Only for `Abiotic_Weapon_QuillRifle_C`, bounded reflected
  property-name hints and directly owned interesting UObject references.
- `FireDelayTimer +0x2590` is a **StructProperty**, not assumed
  to be a float/double firing interval.

These offsets came from reflection in the observed game version but are
**not yet proven gameplay control parameters**. A changed number after
firing is suggestive, not proof that writing it would modify actual
fire rate or recoil. No memory writes, patching, engine method calls, or
injection; F2 and F12 remain inactive. The normal Box ESP stays enabled.

Windows MSVC compilation and real gameplay behavior are unverified until
the user builds and tests the draft PR.
